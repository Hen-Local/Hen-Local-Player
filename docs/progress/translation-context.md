# Dialogue context in generated translations

Before this change, ordinary sessions translated each recognized utterance independently. The optional context setting passed at most the preceding row’s text. A seek could translate a line before its predecessor had been recognized, and the cache accepted that first result even when the missing context later became available.

The desktop and CLI now default to contextual translation for new preferences and respect a saved choice. They send the full current utterance as the source to the local Hy-MT2 1.8B Q4_K_M model. Background comes from up to three immediately preceding, successfully recognized utterances on the same media and audio track. The cutoff is 30 seconds before the current onset, 8 seconds of silence between adjacent utterances, or 1,024 UTF-8 bytes of background. A language change or unrecognized row ends the window. Lines are sent in playback order.

The background and current source occupy separate fields in Hy-MT2’s Structured Data 2 user prompt. The backend uses the pinned llama-server b11429. [Upstream prompt templates](https://github.com/Tencent-Hunyuan/Hy-MT2/blob/ff1903ecaa724e10951a23c16817a2413c752b35/README.md#hy-mt2-translation-task-instruction-examples-chinese-english-comparison)

Seeking into a long utterance prioritizes that line. Once its source is available, nearby missing predecessors can be recognized even in lookahead-only mode. A change to the effective source language, current text or preceding context makes the old translation eligible for refresh. Results from superseded inputs are discarded. Only the edited row and its three successors need their input signatures recomputed after recognition. Playback updates reuse those signatures.

Contextual results are saved in the selected track’s `translations/<target>.context.json`. The earlier `<target>.json` remains readable and independently selectable. Previously generated captions appear in the first media-opened event while the new mode processes them. A cached fallback must still match the current source text, target and generation. Contextual captions remain available on reopen with the models offline.

## Checks on Apple Silicon

- [x] `cargo test --locked -p hlp-pipeline --lib` passed the timeline regressions for chronological ordering, Unicode byte limits, language boundaries, silence, incomplete predecessor recognition, seeks inside a long utterance, cached fallback, separate targets/tracks, regeneration and reopen.
- [x] `cargo test --locked -p hlp-pipeline --test contextual_translation -- --ignored` called the installed local Hy-MT2 model and passed. The same English source “Look at the bat.” yielded the sports-equipment and animal senses in separate scenes, each as a single short Chinese translation.
- [x] A six-line spoken test (macOS Samantha voice, 16 kHz WAV) included “Look at the bat.” after two baseball lines and again after two cave lines, with 10 seconds of silence before the scene change. `hlp-cli subtitle baseball-cave.wav --source en --to zh --formats srt --json-progress` ran against an isolated data directory. With context disabled, both lines translated to “看看那只蝙蝠”. With context enabled, the 8.966-second line translated to “看看球棒” and the 29.126-second line to “看那只蝙蝠”. The six source utterances were reused and all six translations ran locally. All nine previously displayed cues were already present in the opening event.
- [x] A second six-line English/Chinese test produced six contextual translations with zero ASR requests. The riverbank sentence stayed on its original interval. A second contextual open reported 0 ASR requests, 0 translation requests and 0.067 seconds of wall time.
- [x] `cargo test --locked -p hlp-pipeline --lib playback_tests -- --ignored --test-threads=1` passed both real playback-session tests in 10.58 seconds. An initial run exposed 18 MT requests while regenerating six lines backwards from a playhead beyond the clip. Background work now waits for pending adjacent context that is eligible for recognition. The line at the playhead and lines beginning in the next two seconds still run immediately. Repeating the real test produced exactly six new ASR and six MT requests during regeneration, followed by a zero-request reopen.
- [x] A synthetic partially completed timeline with 3,600 utterances required zero repeat hashes in the scheduler/status/cue playback path after signatures were cached. Median loop time in the comparison dropped from 11.84 ms to 0.31 ms.
